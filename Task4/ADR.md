| 1 | Оператор кол‑центра банка | Просмотр актуальных ставок по депозитам | Оператор в интерфейсе кол‑центра видит актуальные ставки и условия депозитов для консультирования клиентов. Данные поступают из единого источника правды через API. |

| 5 | DevOps / ИБ / Мониторинг | Контроль доставки и целостности данных | Обеспечивается проверка факта выгрузки файла, его валидности (контрольная сумма, подпись), доступности SFTP и корректности API. При сбоях — автоматические алерты. |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№** | **Требование** |
| :---: | :--- |
| 1 | Актуальность ставок в интерфейсе оператора кол‑центра — не старше 15 минут. |
| 2 | CSV‑файл должен формироваться не реже чем раз в час, а также дополнительно при изменении ставок. |
| 3 | Формат файла — CSV (UTF‑8) с фиксированным набором колонок: product_id, product_name, min_amount, max_amount, rate_percent, currency, start_date, end_date, is_active. |
| 4 | Передача файла — по SFTP с аутентификацией по ключу; файл должен сопровождаться контрольной суммой (MD5/SHA256) либо цифровой подписью. |
| 5 | В передаваемых данных — только продуктовые параметры; персональные данные в файл не включаются. |
| 6 | Мониторинг ключевых операций (выгрузка файла, доступность API, ошибки синхронизации) с настроенными алертами. |
| 7 | Логирование обращений к API ставок и операций выгрузки файлов (кто, когда, результат). |
| 8 | Масштабируемость сервиса кэширования ставок: возможность горизонтального масштабирования для обработки пиковых нагрузок. |
| 9 | Изоляция доступа: API и SFTP должны быть защищены, доступ — только для авторизованных потребителей. |
| 10 | Документация: спецификация формата CSV и описание API (контракт) для поддержки и интеграции. |

### <a name="_qmphm5d6rvi3"></a>**Решение**

**Диаграммы C4:**

- [Контекстная диаграмма](C4_Context.puml)
- [Диаграмма контейнеров](C4_Container.puml)

#### Основные компоненты и интеграции

**Контекстный уровень (C4 Context):**
- **Внешние участники:** операторы кол‑центра банка, операторы партнёрского кол‑центра.
- **Системы:** АБС (источник истины), Сервис кэширования ставок, Система кол‑центра банка, SFTP‑сервер, Внешняя ИС партнёрского кол‑центра.
- **Ключевые потоки:**
  - АБС → Сервис кэширования ставок: передача данных о ставках (только чтение).
  - Сервис кэширования ставок → Система кол‑центра: предоставление ставок через HTTP API.
  - Сервис кэширования ставок → SFTP‑сервер: выгрузка CSV‑файла со ставками.
  - Партнёрский кол‑центр: периодический забор файла с SFTP и импорт в свою ИС.

**Уровень контейнеров (C4 Container):**
- **АБС:** приложение (бизнес‑логика) + БД (хранение ставок, договоров, справочников).
- **Сервис кэширования ставок:**
  - API‑компонент: обработка запросов на получение ставок.
  - Синхронизатор: периодическое чтение данных из АБС и обновление кэша.
  - Экспортер: формирование CSV‑файлов и выгрузка на SFTP.
  - Кэш/хранилище: временное хранение данных для быстрого ответа.
- **Система кол‑центра банка:** интерфейс оператора + бэкенд + БД (заявки, статусы).
- **SFTP‑сервер:** приём и хранение файлов, управление доступом.
- **Внешняя ИС партнёрского кол‑центра:** система партнёра, которая импортирует CSV и отображает ставки операторам.

#### Логика принятых решений

- **Единый источник правды — АБС.** Все потребители работают с репликой/кэшем, что исключает расхождения в данных.
- **Разделение каналов доставки.** Для внутреннего кол‑центра используется API (низкая задержка), для партнёра — файл по SFTP (соответствует ограничениям партнёра).
- **Кэширование данных.** Обеспечивает требуемую актуальность и снижает нагрузку на АБС.
- **Контроль целостности и безопасности.** SFTP с ключами, контрольные суммы/подписи, отсутствие персональных данных в файле.
- **Мониторинг и алерты.** Критичны для своевременного выявления сбоев, влияющих на качество консультаций.
- **Масштабируемость.** Сервис кэширования спроектирован для горизонтального масштабирования под рост нагрузки.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

- **Прямая интеграция партнёрского кол‑центра с API банка.** Не подходит: партнёр не готов к API‑интеграции.
- **Ручная передача файлов (например, XLS по почте).** Неприемлемо: высокие риски ошибок и потери контроля версий.
- **Отдельный реестр ставок вне АБС.** Неприемлемо: создаёт второй источник истины и риск расхождений.
- **Отказ от предоставления ставок в кол‑центры.** Ухудшает клиентский опыт и увеличивает нагрузку на линию.

---

**Недостатки, ограничения, риски**

- **Риск рассинхронизации данных.**  
  *Смягчение:* мониторинг, алерты, повторные попытки выгрузки, контроль контрольных сумм.
- **Ограниченная частота обновления для партнёра.**  
  *Смягчение:* для внутреннего кол‑центра обеспечена актуальность не старше 15 минут; для партнёра частоты раз в час достаточно в MVP.
- **Зависимость от SFTP‑инфраструктуры.**  
  *Смягчение:* резервные каналы передачи, повторные попытки, уведомления об ошибках.
- **Безопасность передачи файлов.**  
  *Смягчение:* аутентификация по ключам, шифрование, контроль доступа, аудит операций.
- **Нагрузка на АБС.**  
  *Смягчение:* только чтение данных, кэширование, ограничение частоты запросов, использование оптимизированных представлений.
- **Сложность поддержки формата CSV.**  
  *Смягчение:* чёткая спецификация, версионирование файлов, контрактные тесты и тестовые прогоны перед внедрением изменений.
